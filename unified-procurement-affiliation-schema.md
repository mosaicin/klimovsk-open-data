# Единая аналитическая схема: закупки ЕИС и аффилированность

## 1. Основной принцип

Не следует складывать все сведения в одну плоскую строку. Закупка, контракт, участник, ставка, документ и связь между организациями имеют разную кратность. Правильная модель состоит из таблиц фактов и таблиц связей, объединённых устойчивыми ключами. Итоговый «аналитический вид» строится только после нормализации и дедупликации.

## 2. Сущности и ключи

| Таблица | Одна строка | Первичный ключ | Основные поля |
|---|---|---|---|
| `procurements` | одна процедура | `procurement_id` | ИКЗ, закон, способ, заказчик, предмет, ОКПД2, НМЦК, даты |
| `lots` | один лот | `lot_id` | `procurement_id`, предмет, НМЦК лота |
| `contracts` | один контракт | `contract_id` | `procurement_id`, заказчик, поставщик, цена, статус, исполнение |
| `participants` | один участник | `participant_id = INN` | ИНН, ОГРН, название, регион, дата актуальности |
| `participations` | участник в процедуре | `procurement_id + participant_id` | допуск, роль, результат, место, финальная цена |
| `bids` | одна заявка/ставка | `bid_id` | процедура, участник, время, цена, номер шага |
| `documents` | один файл/документ | `document_id` | URL, тип, дата, SHA-256, источник, уровень подтверждения |
| `corporate_links` | одна предполагаемая связь | `link_id` | субъект A, субъект B, тип связи, дата, источник, статус |
| `technical_indicators` | индикатор по процедуре/паре | `indicator_id` | тип, значение, метод, порог, источник, альтернативное объяснение |
| `execution_events` | событие исполнения | `event_id` | контракт, тип события, дата, сумма, документ |

Участников следует связывать по ИНН, а юридические лица дополнительно проверять по ОГРН. Название и адрес являются атрибутами, но не ключами: они могут изменяться или совпадать у разных организаций.

## 3. Уровни доказательности

| Уровень | Значение | Пример |
|---|---|---|
| A | официальный первичный документ | карточка ЕИС, протокол, выписка ФНС, решение ФАС |
| B | официальный вторичный источник | официальный отчёт, пресс-релиз, открытая статистика |
| C | агрегатор или справочный источник | карточка тендерного агрегатора, каталог адресов |
| D | гипотеза/непроверенное сообщение | слух, предположение, неподтверждённая связь |

В аналитическом отчёте факты уровней A–B не следует смешивать с индикаторами C–D. В итоговом поле обязательно хранится ссылка на источник и дата его проверки.

## 4. Ключи объединения

Надёжное объединение выполняется в следующем порядке:

1. `procurement_id` связывает процедуру ЕИС с лотами, участниками и ставками.
2. `contract_id` связывает процедуру с конкретным контрактом и событиями исполнения.
3. `participant_id` на основе ИНН связывает участника с ЕГРЮЛ, РНП, КАД и корпоративными связями.
4. `document_id` связывает вывод с оригиналом, URL, датой и хэшем.
5. Для парных индикаторов используется канонический ключ: меньший нормализованный ИНН первым, больший вторым, чтобы A–B и B–A не стали двумя строками.

## 5. Расчёт индикаторов

| Индикатор | Формула/правило | Интерпретация |
|---|---|---|
| Снижение | `(NMCK - final_price) / NMCK` | ценовый результат, не доказательство координации |
| Повторяемость пары | число сопоставимых процедур с парой A–B | основание проверить группу и рынок |
| Ротация | распределение побед между участниками | проверяется контрольной группой |
| Синхронность | доля межучастниковых ставок в окне Δ | зависит от нулевой модели и логов |
| Корпоративное совпадение | общий руководитель/участник/адрес с датой | требует официальной выписки |
| Документное сходство | одинаковый хэш/метаданные/ошибки | требует оригинальных файлов |
| Техническое совпадение | IP/сессия/устройство/ЭП | обычно доступно только оператору или органу |

Нельзя создавать единый «балл вины». Допустим отдельный риск-скор для приоритизации ручной проверки, но он должен показывать состав индикаторов, веса, источники и альтернативные объяснения.

## 6. Валидации качества

Перед объединением нужно нормализовать ИНН и ОГРН как строки, даты привести к ISO 8601 и проверить часовой пояс, суммы — к числовому типу с точностью до копеек. Необходимо выявлять дубли реестровых номеров, контракты без процедуры, участников без ИНН, ставки без времени и источники без URL.

Конфликты не следует молча перезаписывать. Если название или руководитель различается между датами, сохраняйте исторические записи с периодом действия и ссылкой на источник. Если две карточки агрегатора противоречат ЕИС, приоритет имеет официальный документ.

## 7. Аналитический вид

После нормализации создаётся представление `procurement_affiliation_view`, где одна строка соответствует паре «процедура × участник», а индикаторы присоединяются агрегатами:

```text
procurement_id
contract_id
participant_inn
participant_name
customer_inn
published_at
subject
okpd2
nmck
final_price
reduction_pct
participant_role
winner_rank
pair_repeat_count
corporate_link_count
technical_indicator_count
execution_event_count
evidence_level_min
evidence_level_max
source_document_count
manual_review_status
```

Такой вид удобен для фильтрации, но исходные таблицы должны сохраняться отдельно, чтобы любой показатель можно было воспроизвести.
